Hop	Device	In-interface	Decision	Out-interface, next hop
0	host3		Default route via 10.1.5.1	eth1
1	srl3	e1-2 (10.1.5.1)	Static route 10.1.4.0/24	e1-1 to 10.1.3.1
2	srl1	e1-3 (10.1.3.1)	Static route 10.1.4.0/24	e1-2 to 10.1.2.2
3	srl2	e1-1 (10.1.2.2)	Connected route 10.1.4.0/24	e1-2
4	host2	eth1 (10.1.4.2)	Delivered

The return path is the forward path in reverse because each router has a static route for both end subnets, and srl1 is the only transit between srl2 and srl3. There is no alternative route, so asymmetric routing can't happen in this topology.

Expected traceroute output
bash
docker exec clab-routing-basics-host2 traceroute 10.1.5.2
docker exec clab-routing-basics-host3 traceroute 10.1.4.2
host2 -> host3                 host3 -> host2
1  10.1.4.1  (srl2)            1  10.1.5.1  (srl3)
2  10.1.2.1  (srl1)            2  10.1.3.1  (srl1)
3  10.1.3.2  (srl3)            3  10.1.2.2  (srl2)
4  10.1.5.2  (host3)           4  10.1.4.2  (host2)

Each router answers with the address of the interface the probe arrived on. That is why srl1 shows as 10.1.2.1 going one way and 10.1.3.1 coming back.

Checking each hop on the routers
show network-instance default route-table ipv4-unicast route 10.1.5.2
show network-instance default route-table ipv4-unicast route 10.1.4.2

Run these on each router. If a hop is wrong, the route lookup shows which next hop it actually uses.

The TTL decreases by 1 at each router, so the packet arrives at host3 with TTL 61 (64 minus 3 routers). That is a quick way to confirm three router hops.
